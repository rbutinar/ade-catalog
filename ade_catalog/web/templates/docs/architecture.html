Database Backends

ade-catalog supports two database backends, switchable via the CATALOG_DB_BACKEND environment variable.

Supabase (default)

  • PostgreSQL managed by Supabase
  • Built-in auth (email, SSO)
  • Object storage for files
  • Cloud-native, zero maintenance
  • Multi-tenant with RLS

SQL Server (on-prem)

  • Self-hosted SQL Server
  • No auth layer (open access)
  • Local file storage
  • Full control, enterprise networks
  • View-based isolation

All queries are written in PostgreSQL dialect and automatically translated to T-SQL when using SQL Server backend.

Multi-tenancy

Organization (auth_meta.organizations)
├── Users (auth_meta.user_org_memberships)
│   ├── owner — full access + admin
│   ├── admin — manage users in org
│   ├── editor — edit metadata
│   └── viewer — read only
│
├── Views (catalog_meta.catalog_views)
│   ├── "Client Fabric" (view_id=7)
│   ├── "Client Power BI" (view_id=8)
│   └── "Production Scan" (view_id=9)
│
└── Storage (Supabase Storage)
    └── {org_id}/
        ├── extractions/fabric/...
        ├── extractions/databricks/...
        └── exports/...
