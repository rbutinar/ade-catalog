Understanding Lineage

What is Data Lineage?

Data lineage shows how data flows through your analytics environment. It answers questions like:

  • Where does this table's data come from? (upstream)
  • What reports and dashboards use this table? (downstream)
  • If I change this column, what will break?
  • Which notebooks transform this data?
  • How does data flow from source to Power BI report?

Cross-Platform Lineage

ade-catalog builds lineage across platforms. A single lineage graph can show: 

Source Files (CSV/Excel)
    ↓ ingested by
Databricks Notebook (bronze layer)
    ↓ transforms to
Fabric Lakehouse Table (silver)
    ↓ aggregated by
Fabric Warehouse Table (gold)
    ↓ consumed by
Power BI Dataset
    ↓ visualized in
Power BI Report

Relationship Types

Lineage edges are categorized by type:

Data Flow

feeds, produces, consumes, transforms_to, copies_to

Structure

belongs_to, contains, hosted_in, stored_in

Orchestration

triggers, schedules, depends_on, runs_after

Reference

displays, uses, references, visualizes, calculates

Using Lineage

Lineage is available in two ways:

Web UI (coming soon)
Interactive lineage graph on object detail pages. Select direction (upstream/downstream), depth, and relationship filter. Rendered as a Mermaid flowchart.
MCP / AI Agents
Use the get_lineage tool via MCP to ask an AI assistant: "Show me what feeds into the gold_sales table" or "What downstream reports would break if I change this column?"
